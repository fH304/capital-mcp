# المرحلة الأولى: وحدة فحص الأخبار

هذه وحدة تجهيز واختبار فقط، وليست البوت الذكي المكتمل. لا تتصل بكابيتال ولا تنفذ صفقات، ولا تغيّر ملفات autotrader.

تشغيل الاختبارات: python -m unittest smarttrader.test_news
تشغيل فحص واحد: python -m smarttrader.news

متغيرات الفحص: EODHD_API_KEY وNEWS_STATE_PATH. المسار الافتراضي /var/data/smart-news.sqlite. احفظ الملف على قرص مستمر. لا تضع المفتاح في الكود أو سجلات التشغيل.

تطلب الوحدة أخبار EURUSD.FOREX، وتحفظ وقت النشر والاستلام، وتستبعد المنشور الأقدم من ست ساعات أو بتاريخ مستقبلي أو دون منطقة زمنية، وتحذف التكرار بحسب رابط المصدر. الأخبار نصوص غير موثوقة؛ لا تتحول إلى أوامر أو اتجاه شراء/بيع تلقائيًا.

الميزانية المحلية الافتراضية 20 وحدة طلب يوميًا بالتوقيت العالمي؛ الحجز يسبق الشبكة ويشمل الطلب الفاشل. الطلب يستهلك خمس وحدات، والتحديث كل ست ساعات. هذه ليست مزامنة مع رصيد مزود البيانات: الاستخدام خارج الوحدة قد يستنفد الرصيد. لا ترفع الحدود أو تفعّل مراقبة أسواق كثيرة قبل تحديد الخطة والميزانية. الأخبار القديمة في عطلة نهاية الأسبوع قد تُستبعد وهذا لا يُعد خلل اتصال.

المتبقي: تقويم اقتصادي موثوق مع صلاحيات وتوقيت واضحين، مسح الأسواق وتحويل العملات وحجم العقود، تحليل عدة أطر زمنية، مراجعة آلية للأخبار محددة التكلفة، قواعد المخاطر، مسار تنفيذ منفصل للحساب التجريبي وتسوية نتائج الأوامر، وتقييم الاستراتيجية. لا توجد نسخة حقيقية جاهزة، ولا دليل ربحية أو اختبار تنفيذ مباشر للنسخة الجديدة.

المصدر: https://eodhd.com/financial-apis/stock-market-financial-news-api

## حساب حجم الصفقة (وحدة مستقلة لم تُربط بالتنفيذ)

smarttrader/sizing.py يحسب الحجم من قيمة الحساب الحالية بما يشمل الربح والخسارة العائمة، ومسافة الوقف والسبريد وقيمة النقطة وتحويل عملة التسعير إلى عملة الحساب. يراعي الهامش الحر والمخاطر المفتوحة والمتبقي من حد الخسارة اليومي والحد الأدنى وتدرج الحجم لدى الوسيط. يرفض الصفقة إن كان الحد الأدنى أكبر من الميزانية، ولا يرفع الحجم لإجبار التنفيذ.

الإعداد المبدئي الحسابي الموروث من النسخة القديمة 0.25% لكل صفقة و0.5% إجمالي مخاطرة مفتوحة؛ ليس دليلاً على ملاءمة الاستثمار. الحد اليومي المطلوب للتجربة 250 دولار منفصل عن حجم مخاطرة الصفقة. مراقب الخسارة اليومي وتسوية الصفقات لم يُنفذا بعد في النسخة الجديدة. على موصل كابيتال توفير قيم العقود والتحويل والهامش بعد التحقق؛ لا يفترض الكود أن قيمة النقطة واحدة لكل سوق. لا يضمن الوقف الخسارة عند الانزلاق أو الفجوات.

## سياسة الحجم والرافعة حسب التحليل

policy.py يربط تقييم الفرصة بحساب الحجم. النتيجة المقبولة تخاطر حسابيًا بنسبة 0.125%؛ النتيجة الإيجابية تسمح بنسبة 0.25% فقط عند نجاح بوابة تقييم مستقلة خارج العينة. هذه بوابة مطلوبة وليست تقييمًا تم إنجازه: لا يجوز أخذ validation_passed من مخرجات النموذج. النتيجة الرافضة تمنع الدخول. لا توجد زيادة الحجم بعد خسارة أو مضاعفة تلقائية.

الرافعة المقترحة هي أقل قيمة يتيحها الوسيط ضمن سقف maximum الذي يحدده المشغل وتكفي ميزانية الهامش. لا تغيير عند وجود مراكز أو أوامر معلقة من الفئة نفسها؛ إما الحفاظ على القيمة أو رفض المقترح. لا يوجد موصل PUT أو تفعيل تغيير الرافعة في هذه المرحلة. على الموصل قراءة إعدادات الحساب الحالية والقيم المتاحة، والتحقق من الصفقات والأوامر، ثم إعادة جلب قواعد السوق وإعادة الحساب والتحقق بعد أي تعديل قبل الدخول. المقترح يفترض الهامش = القيمة الاسمية / الرافعة ولا يغني عن قواعد السوق الفعلية. تعديل الرافعة لا يغيّر حجم صفقة قائمة؛ زيادة الحجم أثناء الصفقة ليست منفذة.

توثيق API: https://open-api.capital.com/ (GET وPUT /accounts/preferences).

## المراقبة المتوازية ومقترحات الخروج

monitor.py يشغّل ثلاث مهام مستقلة: متابعة المراكز كل خمس ثوان، فرص الأسواق كل دقيقة، وأخبار كل ست ساعات ضمن حد وحدة الأخبار المجاني. هذه فترات إطار الاختبار وليس خدمة منشورة. مهام الشبكة الفعلية لم تُربط بالإطار، وتحتاج مهلات وموصلات مستقلة وآمنة للمتزامنة. لا تشارك API القديم بين الخيوط دون معالجة جلسات الدخول وحدود الطلبات.

تعطل الأخبار لا يوقف متابعة المراكز، لكنه يمنع الدخول الجديد. يظل الدخول ممنوعًا حتى تحديث كل مصدر مطلوب ببيانات قابلة للاستخدام. يحتاج news job فحص عمر محتوى الأخبار نفسه؛ حد عمر تحديث المهمة لا يكفي.

الخروج هنا مقترح close_intent وليس أمر إغلاق: تجاوز الحد اليومي، فقدان وقف الوسيط، اختراق وقف الخسارة بسعر التنفيذ، أو بطلان سبب الدخول/خبر معاكس بدليل حديث وتقييم مستقل. بيانات قديمة أو سوق مغلق تسجل alert بدل الادعاء بأن الإغلاق ممكن. لا تغلق الوحدة صفقات لا تخص البوت. مراقب الحد اليومي وتوثيق ملكية المراكز والتأكيدات وتسوية الإغلاق ما زالت تحتاج تنفيذًا وربطًا. يجب حجز طلب الإغلاق دائمًا قبل إرساله وعدم تكرار الطلب عند نتيجة ملتبسة.

لا يمكن ضمان التشغيل أو إغلاق الصفقات في كل لحظة؛ انقطاع الاتصال وإغلاق السوق والفجوات قد تمنع التنفيذ. استمرار التشغيل 24/7 يختلف عن استمرار تحديث أخبار مدفوعة: حد الخطة المجانية لا يكفي لمراقبة الأخبار بوتيرة دقيقة لعدة أسواق. لا يوجد تحليل تعلم آلي مثبت أو دليل ربحية في هذا الإطار.

## وصلة تحليل OpenAI

analysis.py يستخدم Responses API بمخرجات JSON مقيدة بالمخطط، دون إعطاء النموذج أدوات تنفيذ. يحتاج مفتاحًا ونموذجًا محددًا من المشغل ومسار قاعدة بيانات مستقلًا. حد الاستدعاءات الافتراضي أربعة يوميًا، وحجز الطلب قبل الشبكة يشمل الفشل؛ هذا حد عدد طلبات وليس سقف تكلفة بالدولار. لا توجد إعادة تلقائية للطلب الفاشل. الإدخال محدود بـ30 كيلوبايت والإخراج بـ2000 توكن.

يرفض أسعارًا أقدم من 30 ثانية وأخبارًا أقدم من ست ساعات، ويتحقق مرة أخرى بعد استلام الرد. يرفض الاستشهاد بمقال غير موجود، ومخرجات تغير حجم المخاطرة، ومستويات وقف/هدف غير منطقية، ونسبة عائد إلى مخاطرة أقل من 2، ومقترح إغلاق مركز غير مملوك. WAIT نتيجة طبيعية ولا تضمن كثرة الصفقات أو الربح. ثقة النموذج الذاتية لا ترفع الحجم.

الوصلة لم تختبر بمفتاح فعلي أو رصيد فعلي. اختبارات الشبكة بمحاكاة الردود فقط. الوحدات ليست برنامج تداول مكتملًا: لا توجد نقطة تشغيل تجمع مصادر السوق والأخبار والتحليل بالمخاطر وتنفيذ الأوامر وتسويتها. لا ترفعها إلى خدمة البوت القديم ولا تغيّر مسار Dockerfile إلى ملف غير موجود. استكمال الربط واختباره ثم النشر والتأكد من السجلات شروط منفصلة قبل وصف البوت بأنه مفعل.

تشغيل الاختبارات المجمعة:
python -m unittest smarttrader.test_analysis smarttrader.test_news smarttrader.test_sizing smarttrader.test_policy smarttrader.test_monitor

توثيق OpenAI الرسمي: https://developers.openai.com/api/docs/guides/structured-outputs

## ربط التحليل بحجم الصفقة وسجل التنفيذ التجريبي

coordinator.py يعيد فحص الأسعار الحالية بعد التحليل، ويربط المقترح بحساب الحجم وفق المخاطر والهامش. الحساب التجريبي المحدد فقط مسموح؛ البيانات الحالية للحساب والأوامر والمراكز والعقد مطلوبة. المرحلة الأولى ترفض الدخول في حساب يحتوي مراكز أو أوامر حتى يكتمل ربط الملكية ومراقبة الخروج. لا ترفع ثقة النموذج حجم المخاطرة ولا تغير الرافعة.

الوضع الافتراضي preview لا يرسل أي أمر. عند تفعيل المسار البرمجي يحتفظ بسجل SQLite قبل الإرسال، ويمنع تكرار إشارة السوق/الشمعة بعد إعادة التشغيل. فشل الإرسال أو اختلاف بيانات تأكيد المركز يحجز الحساب بحالة uncertain؛ لا توجد إعادة محاولة تلقائية ولا مسح تلقائي لهذا الحجز.

اختبارات test_coordinator.py تستخدم وسيطًا وهميًا، ولا توجد حتى الآن وصلة Capital فعلية لهذه الوحدة أو برنامج تشغيل قابل للنشر. إثبات نجاح الوحدات لا يعني اختبار تنفيذ لدى الوسيط. يلزم أيضًا ربط مصادر الأطر الزمنية والتقويم والحد اليومي وتسوية المركز وإغلاقه قبل تشغيل النسخة الجديدة. لا تنشر هذه المرحلة مكان البوت القديم.

python -B -m unittest discover -s smarttrader -t .
