# بوت Capital التجريبي — نسخة أولية للاختبار

هذه النسخة مستقلة عن إضافة Capital Demo MCP الحالية للقراءة فقط. لا تحتاج تغيير remote.py أو متغير CAP_ALLOW_TRADING في خدمة MCP. لا يوجد وضع للحساب الحقيقي في هذا البوت، وعنوان API التجريبي ثابت داخل الكود.

## ما الذي يفعله؟

- يفحص GOLD وSILVER وUS500 وUS100 وUS30 وEURUSD وGBPUSD وAUDUSD وBTCUSD وETHUSD كل دقيقة.
- يستخدم تقاطع EMA20 وEMA50 على شموع 15 دقيقة مغلقة فقط. لا توجد أخبار أو نماذج ذكاء اصطناعي ضمن هذه النسخة، ولا يُعد هذا نظامًا مثبت الربحية.
- يتطلب 100 شمعة مغلقة على الأقل، و15 شمعة أخيرة متصلة، وأسعارًا حديثة وغير متأخرة.
- وقف الخسارة المستهدف ضعف متوسط المدى الحقيقي لآخر 14 شمعة، والهدف ضعف مسافة الوقف. هذا متوسط بسيط للمدى الحقيقي، وليس Wilder ATR.
- يخصص مخاطرة مخططة لا تزيد على 0.25% لكل صفقة، مع سماح للسبريد، وإجمالي مخاطر مخططة 0.5%. الوقف غير مضمون، والانزلاق قد يجعل الخسارة أكبر.
- صفقتان مفتوحتان كحد أقصى، وصفقة واحدة لكل فئة، وأربع محاولات دخول يوميًا. ترتيب الفحص ثابت؛ لا يدعي اختيار أفضل فرصة في السوق.
- لا تتجاوز القيمة الاسمية للصفقة 50% من حقوق الحساب، والهامش التقديري 10% من المتاح. قد تكون أحجام بعض الأسواق أقل من الحد الأدنى، وعندها يتجاهلها البوت.
- يوقف الدخول عند انخفاض حقوق الحساب 2% عن أول قراءة في اليوم. اليوم يبدأ الساعة 00:00 UTC، أي 04:00 بتوقيت الإمارات. لا يغلق جميع الصفقات عند بلوغ الحد؛ تبقى أوامر الوقف والهدف الخاصة بكل صفقة.
- يرفض العملات غير USD والعقود ذات lotSize أو scalingFactor غير 1 إلى أن تراجع طريقة حسابها.
- يحفظ دفتر الصفقات في SQLite على قرص دائم. الإشارة نفسها لا تُرسل مرتين، حتى بعد إعادة التشغيل.

## الفرق بين الوضعين

`BOT_MODE=paper` هو الوضع الافتراضي. يقرأ بيانات حساب Capital التجريبي لكنه لا يرسل أي أوامر تداول. الرصيد الافتراضي يبدأ من رصيد الحساب عند أول تشغيل ويُحفظ بعد ذلك بصورة مستقلة.

المحاكاة تستخدم أسعار bid/offer وقت الفحص كل دقيقة؛ لا تلتقط كل حركة داخل الدقيقة، ولا تحتسب التمويل الليلي والعمولات. نتائجها لا تمثل اختبارًا تاريخيًا شاملًا أو ضمانًا لجودة التنفيذ.

`BOT_MODE=demo` يرسل أوامر إلى حساب Capital التجريبي فقط. يتطلب متغيرًا إضافيًا `BOT_ARMED=DEMO_ONLY`. لا تستخدمه قبل مراجعة سجلات المحاكاة وتجربة التنفيذ التجريبي والإيقاف والحماية. اختبارات الوحدة الحالية تستخدم API محاكى؛ لم تُرسل صفقة فعلية أثناء تجهيز هذه الملفات.

## الملفات

أضف الملفات داخل مجلد `autotrader` في مستودع GitHub `fH304/capital-mcp`:

- `__init__.py`
- `bot.py`
- `Dockerfile`
- `test_bot.py`
- `README_AR.md`

ملف `render.yaml` اختياري إذا أردت استخدام Blueprint. رفع ZIP إلى GitHub لا يفك ضغطه؛ فكّه أولًا وضع الملفات في المسارات المذكورة. من الهاتف يمكن إنشاء الملفات عبر GitHub > Add file > Create new file، مثل `autotrader/bot.py`، ولصق محتوى الملف.

## إنشاء خدمة Render من الهاتف

1. بعد إضافة الملفات إلى GitHub افتح https://dashboard.render.com/ واختر New > Background Worker.
2. اختر المستودع `fH304/capital-mcp` والفرع `main`، وDocker، واترك Root Directory فارغًا.
3. اجعل Dockerfile Path يساوي `autotrader/Dockerfile` وDocker Context هو جذر المستودع. لا تستخدم Dockerfile القديم الخاص بخدمة MCP.
4. شغّل نسخة واحدة فقط. اختر Starter بعد مراجعة السعر النهائي. الخدمة والقرص مدفوعان، ولم يشترِ هذا العمل أي خدمة أو ينشرها.
5. أضف قرصًا دائمًا بمسار `/var/data` وحجم 1GB. تحتاج حالة البوت إلى هذا القرص؛ ملفات Render العادية تضيع عند إعادة التشغيل.
6. أضف المتغيرات التالية. أدخل الأسرار مباشرة في Render؛ لا ترسلها في المحادثة ولا تضعها في GitHub.

| KEY | VALUE |
| --- | --- |
| CAP_ENV | demo |
| BOT_MODE | paper |
| BOT_STATE_PATH | /var/data/paper.sqlite |
| BOT_ACCOUNT_ID | رقم الحساب التجريبي الكامل الذي تأكدت منه؛ الحساب المتصل حاليًا ينتهي بـ4558 |
| CAP_API_KEY | مفتاح API المحفوظ عندك |
| CAP_IDENTIFIER | بريد دخول Capital لنفس الحساب |
| CAP_API_PASSWORD | كلمة المرور الخاصة بمفتاح API |

لا تحتاج GITHUB_CLIENT_ID أو GITHUB_CLIENT_SECRET أو JWT_SIGNING_KEY لهذه الخدمة؛ تُستخدم في خدمة MCP الحالية فقط.

7. Deploy، ثم افتح Logs. ابحث عن `heartbeat` مع `mode=paper`. قد تظهر `market_skipped` أو لا تظهر أي صفقة لأن شروط الدخول غير متحققة. لا تعتبر غياب الصفقات خطأً وحده.

## اختبار الملفات محليًا

من جذر المستودع، باستخدام Python 3.12:

```sh
python -m unittest autotrader.test_bot -v
```

اختبارات الوحدة تغطي رفض live، والأسعار القديمة، والشموع غير المغلقة، وحساب الحجم، وتغير الحساب، والصفقات المكررة، وإعادة التشغيل، وتعطل الرد بعد إرسال الأمر، وتأكيد الصفقة والتحقق من الحماية. لا تحتاج مفاتيح لتشغيلها.

## عند المراجعة قبل التنفيذ التجريبي

تحقق من عمل المحاكاة ومنطق الإشارات والأحجام لعدة جلسات سوق. راجع معًا النتائج والسبريد والتكاليف والتراجع قبل الانتقال. لا يوجد وقت ثابت أو عدد صفقات يثبت الربحية.

إذا قررت اختبار إرسال أوامر تجريبية لاحقًا، أوقف خدمة المحاكاة أولًا، وغيّر `BOT_MODE` إلى `demo`، وأضف `BOT_ARMED=DEMO_ONLY`، واستخدم دفترًا جديدًا `/var/data/demo.sqlite`. لا يحوّل البوت صفقات المحاكاة إلى صفقات Capital. لا تشغّل عاملين أو تتداول يدويًا على نفس الحساب خلال الاختبار.

## الإيقاف والأخطاء

- من Render استخدم Suspend لإيقاف الخدمة. هذا يوقف البرنامج؛ لا يغلق الصفقات الموجودة في Capital. تُدار الصفقات القائمة من تطبيق Capital، وتبقى حماية الوقف والهدف التي قبلها الوسيط.
- `HALTED_REVIEW_REQUIRED` يعني توقفًا محفوظًا بسبب خطأ. إعادة التشغيل وحدها لا تستأنف إرسال الصفقات.
- عند فشل اتصال أثناء الإرسال قد يكون الأمر قد نُفّذ. يحفظه البوت `pending` ويتوقف؛ لا تعاود الإرسال ولا تمسح الدفتر قبل مطابقة الأوامر والصفقات في Capital.
- إذا ظهرت صفقة بلا حماية راجعها فورًا في Capital. التوقف عن فتح صفقات جديدة وحده لا يعالج مركزًا موجودًا بلا وقف.
- لا ترسل المفاتيح أو كلمات المرور أو قاعدة البيانات التي تحتوي تفاصيل حسابك في المحادثة. أرسل رسالة الخطأ أو صورة Logs بعد إخفاء المعلومات الشخصية.
